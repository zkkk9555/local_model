## 0. 一条结论
**8G 的「极限」不是 200K，而是 36K 预算 + 4K 输出、KV 用 NVFP4**——这是 KVMem 作者 FirePKU 在 ModelScope 给的 8G 官方推荐配置（配 6.18 GB 的 Bonsai2-T5-MTP-Q4）。我们现在的 --kv-capacity 40000 / rk2v4-e8 恰好压在这条线上；想再往上不是加池，而是换 KV 精度 + 换 draft 机制（DFlash2 vs MTP）。另：**NInfer 原生吃 Bonsai 三元权重后单路已能跑 130 tok/s（沈三殊 383 赞）**，说明我们 97-98 还有换算空间，瓶颈不在权重格式。

## 2. 8G 极限配置：目前唯一「官方口径」的完整参数表（源头已核到 README）
来源：ModelScope KVMem/Bonsai2-27B-T5-MTP-Q4-NInfer 的 README（我直接 curl 取的原文，非二手），配 KVMem v0.19.0-rc1 + NInfer 后端。

| 参数 | 推荐值 |
| --- | --- |
| 驻留预算 budget | 36K = 36,864 tokens |
| 输出预留 gen reserve | 4K = 4,096 tokens |
| KV 类型 | NVFP4 |
| 推测解码 | MTP，固定 3 个 draft token |
| GDN 状态精度 | FP16 |
| Prefill 批量 | 256 tokens |
| 最大并发 | 1 |
| CUDA Graph | 开启，保留 256 MiB 余量 |
| Thinking | 关闭 |

同页实测（RTX 5050 Laptop 8GB / 35W / 2026-10-28）：36,669 tokens 输入后完整生成 4,096 tokens，**约 22 tokens/s，采样显存峰值 6.78 GiB（6,944 MiB）**。
文件本体 6.18 GB（Bonsai2-T5-MTP-r3-Q4.ninfer）；T5 = 三值权重格式（不是 5-bit），Q4 指的是 MTP 矩阵量化。页面明确：「若显存不足，优先下调 budget，保留 4K 输出预留与 CUDA Graph 余量」。

## 4. 坑（本轮新增，按赞/可信度排序）
- **循环输出**：8G Bonsai「前 10 轮正常，第 11 轮的回答就是第 10 轮里夹杂了 1-2 句新内容」，codex 蹬了一天没解决（BV1KtHD6kEi7 评论 里世界滴神 1 赞）。
- **自截断**：不思考模式经常截断、CoT 也经常截断，原因是「模型自己输出停止 token」（BV1gxeY6PEU4 评论 bili_402003899 13 赞）。
- **工具调用死循环**：llama.cpp 官方 release 在 pi agent 里「调用完工具就开始无限循环输出逗号」，换新上下文也不行，怀疑上游 bug（同上 yazi_au 3 赞）。
- **思考 token 失控**：五子棋一道题思考 2 万 token（同上 月下独翁 31 赞）；32k token 后自动中断（BV1MTH969EAS）。→ 对 agent 用必须设思考上限。
- **KV 选 FP16 直接腰斩**：16G 卡上 128K+FP16 掉到 14 t/s，换 Q8 才回到 40-46（BV1TLhB6vE8j）。
- **视觉会掉 CPU**：加图片让它识别时「不跑 GPU 而跑 CPU」（BV1xfx56JEW3 评论 风暴鲁鲁 3 赞）；另有 0.19 监控页在 GPU 忙时整页卡死（同页 岁月平静 1 赞）。
- **客户端兼容**：「能接 opencode，接不了 DSH」（BV1TLhB6vE8j 评论 红豆猫29 2 赞）——与我们 DSH 集成相关，需单测。
- **上下文消耗差异**：同题两模型消耗上下文「至少差一倍半」（同上 流畅更新 4 赞）→ 预算规划要按最坏算。
- **8G 硬塞低价值**：「8G 能跑，没多大实际意义」（BV1gxeY6PEU4 评论 delcompben 3 赞）；另有「8G 速度就 3」（BV1KtHD6kEi7 评论 1 赞）。
