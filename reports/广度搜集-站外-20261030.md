## 1. 27B 三元（Bonsai-2）新存档 —— 三个真正的新东西

### 1.1 ★ DFlash2 草稿头「缩词表」版（10-29，最新）
- URL：https://huggingface.co/kristobalus/Ternary-Bonsai-2-27B-DFlash2-dv98304-GGUF （created **2026-10-29**）
- 文件：Bonsai-2-27B-DFlash2-Q4_K_M-dv98304.gguf **1.28 GB（1.19 GiB）**；-dv81920 **1.25 GB（1.17 GiB）**
- 机制（原文）：草稿头原先复用目标的 248,320 行词表，是每轮投机最贵的一步；这里给草稿头一个**只覆盖 top-N token 的独立头 + d2t 映射**（FR-Spec, arXiv 2502.14856），**草稿头少读 2.5–3× 字节**；目标仍用全词表验证 ⇒ 原文写 "Lossless"，只损失少量接受率。
- 数据 [作者实测，Mac mini M4 16 GB，6 条提示、每臂 72 请求、95% 区间]：原版 23.44 tok/s、接受率 0.624；dv81920 **24.32 tok/s（+3.8% [+1.9; +5.7]）**、接受率 0.636；dv98304 **24.26（+3.5% [+1.5; +5.6]）**、接受率 0.642；覆盖率 99.32% / **99.56%**；额外内存 +106 / +127 MiB；温度 0 输出全等。
- 限制：需**带 PQ2_0 类型 + DFlash2 draft-vocab（d2t）支持的 llama.cpp 分支**，加载时打印 "DFlash draft vocab N of 248320 (d2t)"；mainline 大概率不认。
- **对我们**：思路可搬（NInfer 的 --spec dflash2 若草稿头也吃满词表，缩词表就是白拿 3–5%）；但这份 GGUF 我们吃不了 ⇒ **需要验证**。

## 5. llama.cpp 侧压 KV 的手法（更新我们的算术线）
- **ik_llama.cpp** README 原文要点：
  - "Low perplexity Q4_0 KV cache" — PR #1547 / #1556（https://github.com/ikawrakow/ik_llama.cpp/pull/1547）；
  - Q8_KV 新类型（PR #208）、Q8_0 KV + FlashMLA-2（PR #265）；
  - **--mtp-requantize-output-tensor new_type（PR #1809）** —— 官方提供「MTP 输出张量降精度」开关，正是 1.2 那招的引擎侧对应物；
  - 类型总表见 https://github.com/ikawrakow/ik_llama.cpp/discussions/8 。
- **算术更新（本轮最值钱的一条）**：200K（204,800 token）拆两笔账——
  - 设备常驻：204,800/64 = **3,200 页 × 0.84 MiB（rk2v4-e8）= 2.63 GiB**；权重 5.94 GiB + 运行时约 1.0 GiB ⇒ 只剩约 1.15 GiB ⇒ **只能住约 87.6K token**（与既有 94.7K 天花板同源）。
  - 宿主页：204,800 × **25.12 KiB** = **约 5.02 GiB**（现配 6,144 MiB 其实够到 244K）。
  ⇒ **结论修正：200K 在 8 GB 上不是「算术不可能」，而是「需要 ~87K 设备常驻 + 5 GiB 宿主页 + 分页 host-restore 必须正确」**；真正没过的是第三项（我们实测超池 8/8→2/8→0/8 静默错；NInfer issue #12 是 "Paged KV pool has no free page for host-restore" 显式崩）。
- **对我们**：**立刻可试** = MTP 头 Q4 化（+1–2K 池）；**需要验证** = 5 GiB 宿主页 + 分页回读正确性（200K 的真正闸门）。
