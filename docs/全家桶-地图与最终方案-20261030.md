| 备选 | **llama.cpp KVMem fork**（"③超低显存档"里的 `llama-kvmem-server.exe`） | 同一套"显存池 < 上下文"思路的 llama.cpp 分支，内嵌 sm_89 cubin | ⚠️ 能跑，但慢很多（§4），作并存备胎 |

## 2. 预算公式（起服前先算，别靠运气）

```
红线 redline = 卡总显存 8188 − 运行预留 400 − 桌面 300  =  7,488 MiB
估算 engine_est = 7,254（ptq1+mtp 固定开销，含 5.94 GiB 权重）
                + ceil(pool/64) × 0.8357（rk2v4-e8 每页边际；k8v4 为 1.602）
判定：engine_est ≤ redline 才起，否则拒启
```

实测边际 **0.87–0.90 MiB/页（64 token）⇒ 约 14 MiB / 1k token**，与闸门公式的 0.8357 同量级（保守方向正确）。
`python scripts/plan.py --card 8188 --dtype rk2v4-e8 --pool <N> --mtp` 直接出判定；`--fit` 反解给定 dtype 的最大池。

**两条硬物理事实**（踩过就懂）：
1. **MTP 与 CUDA Graph 在 8 GB 上二选一**。开 `--spec mtp` 就触发 1.32–1.47 GiB 的固定 runtime 预留，作者 8g-fast 原样在 4060 Ti 上直接拒启：`requested Engine runtime reservation requires 1473604096 bytes, but only 1037041664 bytes are available`。不投机时 CUDA Graph 完全可用（`INFO CUDA graphs ready | 144 ms`）。
2. **host_pages + pool_pages ≥ logical_pages**（KVMem 环硬约束）。`--max-context 262144` ⇒ 逻辑 4,096 页，所以**缩池必须同步抬 `--host-kv-mib`**，否则报 `NINFER_KV_WINDOW (KVMem ring) needs a Host KV tier that can hold every page`。

## 3. 最终采用的配置（N7）—— 三档，按用途选，别调参

启动器：`cd /c/Project/local_model && PROFILE=fast GW=1 bash scripts/serve2.sh`

### 档位表

| 档 | PROFILE | 池 / host-kv | 投机 | 实测峰值 | 计数 tok/s | 散文 tok/s | 单问上下文上限 | 用途 |
|---|---|---|---|---|---|---|---|---|
| **日常主力** | `fast` | 16,000 / 4,096 | draft 4 + win 8 | **7,141 MiB**（余 1,047） | **98.1** | 45.7 | 16,000 | 聊天、写稿、日常代码；卡上还留 1 GB 给 OBS/录屏 |
| 长上下文 | `ctx20` | 20,032 / 5,120 | draft 4 + win 8 | 7,197 MiB | 97.6 | ~41 | 20,032 | 需要贴 6k 字文档 |
| 超长上下文 | `long` | 51,200 / 2,816 | 无 | 7,353 MiB | 32.1 | 32.2 | 51,200 | 塞整本说明书；**牺牲 3 倍速度** |
| 极限省显存 | `fast` + `CHUNK=512` | 16,000 / 4,096 | draft 4 + win 8 | **7,067 MiB** | 92.7 | ~43 | 16,000 | 要同时开 OBS 录制/游戏 |
| 旧对照 | `legacy` | 32,000 / 8,192 | draft 4 | 7,439 MiB | 96.6 | 45.3 | 32,000 | **只为 A/B 保留，已越红线 180 MiB，不要日常用** |

*所有臂统一 `--default-reasoning-effort none`*（这是与作者配方的唯一主动偏离：作者 medium 会先吐大段推理，日常用不上）。

### fast 档完整参数（想手敲就照这个）

```bash
export NINFER_KV_WINDOW=16384 NINFER_KV_RETRIEVE=8192
export NINFER_HOST_PAGEABLE=1 NINFER_KV_REUSE_HOSTBACKED=1 NINFER_TERNARY_PTQ1_FAST=1
engine/ninfer-serve-89.exe models/bonsai2_27b_ternary_ptq1_native_mtp.ninfer \
  --host 127.0.0.1 --port 8091 --model-id jinfer-local \
  --max-context 262144 --max-concurrency 1 --max-shared-prefixes 0 --derive-session-keys \
  --prefill-chunk 1024 --default-max-tokens 8192 --default-reasoning-effort none \
  --kv-capacity 16000 --kv-dtype rk2v4-e8 --host-kv-mib 4096 --device-state-slots 0 \
  --no-cuda-graph --gdn-state-fp16 \
  --spec mtp --draft-tokens 4 --mtp-attention-window 8 \
  --presence-penalty 0 --temperature 0.7 --top-p 0.9 --top-k 20 \
  --log-stats-interval-ms 5000 --log-colours off
```

要点：模型路径是**第一个参数**（没有 `--model` 开关）；`NINFER_KV_WINDOW` 是环的门（`NINFER_KV_RING` 新件不读）；env 必须在**同一个 shell** 里 export；**一张卡只起一个引擎实例**（首启会校准并写 `%LOCALAPPDATA%\ninfer\device-profiles.json`，多实例互踩）。

## 4. 实测性能（本机，全部同卡同日）

| 场景 | 数字 |
|---|---|
| 计数/贪婪任务（1..300 续号） | **98.1 tok/s**，MTP 接受率 82.5% |
| 中文散文 300 字（temp 0.7） | **45.7 tok/s** |
| 短问 TTFT | 194 ms（15 token prompt） |
| 19.7k 长文 prefill | **1,022 tok/s**，首 token 19.3 s，decode 65–112 |
| 前缀命中（第二轮） | prompt 只 prefill 7 token，+95–127 ms |
| 冷/热答案一致性 | 15 次 warm 全对（含 5,537 token 前缀 + 第 61 段针） |
| llama KVMem fork 同卡对照 | 36.8 tok/s decode，prefill **387**（我们快 2.7×），显存 6,113 MiB，就绪 6.9 s |

**噪声底**（沈三殊方法论）：计数 tok/s 与峰值可**复现到 0 差**（同一配置两次启动完全一致）；散文是 **±3 tok/s 噪声** ⇒ 散文差 3 以内不算信号。以后自己试参数，先跑两遍同配置量噪声底。

## 5. 怎么用（今天就能用）

```bash
cd /c/Project/local_model
PROFILE=fast GW=1 bash scripts/serve2.sh            # 引擎 8091 + 网关 8081
```
- **客户端 base URL 现在可以只填 8081**（GET/POST 都透传，含 `/v1/models`）。
- 就绪判据：`curl 127.0.0.1:8091/v1/models` 返 200（约 4–8 s；慢是因为在校准 device profile）。
- 客户端一律接 **`http://127.0.0.1:8081/v1`**（网关会按 L0–L3 自动裁超池请求，超池时给可信答复而不是静默错）。
- 调试直连 **`http://127.0.0.1:8091/v1`**（快，但**超池时不可信**：引擎只打 `unverified` 警告然后照答）。
- 停服：`taskkill //F //IM ninfer-serve-89.exe`；网关 `taskkill //F //FI "WINDOWTITLE eq *chat_gateway*"` 或直接按 pid。

**本轮已端到端验证（2026-10-30 06:01）**：
| 检查 | 结果 |
|---|---|
| `/v1/models` | 200，`context_window 262144`，id `jinfer-local` |
| 直连 8091「13×7」 | `91` ✅，0.3 s，usage 21+3 |
| **网关 8081 带 tools** | `finish_reason: tool_calls`，`get_weather({"city":"北京"})` **完整透传** ✅（此前作者 selftest 报 FAIL 只是断言过期，功能正常） |
| **网关 8081 SSE 流** | 8 个 chunk，文本 `1, 2, 3, 4, 5` ✅ |
| 起服后峰值 | **7,141 MiB**（余 1,047） |
| 网关 GET `/v1/models` | 200 ✅（原版网关只处理 POST，GET 返 501，会让 LobeChat/Cherry/Cline 这类客户端「以为连不上」；本轮已给 `tools/chat_gateway.py` 补 `do_GET` 透传） |
| 网关第二轮前缀命中 | `cached_tokens 277`（前缀复用在网关后面照常生效） |

## 6. 禁忌清单（每条都有实测证据，别手贱）

| 不要做 | 后果（原文/证据） |
|---|---|
| `--embedding-q4` / `-q6` | **拒启**：`requires text/token_embedding to be stored as row-split Q8_G32`（PTQ1 制品没有） |
| `--lm-head-draft` | **拒启**：`selected proposal head is absent from artifact` |
| `--mtp-attention-window 4096` | 不省一 MiB，−2.1 tok/s。保持 8 |
| `--adaptive-mtp` / `--draft-tokens 8` | draft8 掉到 79 tok/s（接受率 54%）；adaptive 救不回 |
| `--kv-lease-growth` | 上游 README：池 < 上下文的构型**不要开**；F2 批开了出现"输出被砍到 2 token"，B35 记录其超池静默截断 P0 未修 |
| `--max-concurrency` >1 | 环模式启动即拒 |
| `--max-shared-prefixes` ≠0 | 快失败：`active KV snapshot page ownership is not ordered` |
| 池 < 8 页 / 长输出 free < 10 页 | `pool must hold at least 8 page(s)`；池 1,536 实测缺号回卷 |
| `--kv-dtype nvfp4` | sm_89 无 FP4 |
| `--spec dflash2` / `--disk-kv-*` / `--use-alt-prefix-caching` / `--wddm-evictable-budget` | 分别：多占 1.3–2.07 GiB 且接受率仅 22–47% / 43 MB/s 太慢 / 与环不兼容 / 卡死初始化 |
| 同时驻留两个引擎或 llama fork | 7,141 + 6,113 = 13.2 GiB > 8,188，必定 OOM |

## 7. 未验（诚实清单）

1. **OBS 录制中的峰值显存** —— 余量 1,047 MiB，按估算够，但没实测。要录屏就用 `CHUNK=512`（7,067）更稳。
2. **>16,000 前缀的 canary** —— 超池前缀的行为只用 19.7k 长文验证过"会打 unverified 警告"，多轮改写历史 / 并发未覆盖。
3. `NINFER_KV_RETRIEVE=8192`：我们实测臂都带着它；作者最新 README-pack 的口径是"不设"。**两种口径的速度/正确性差异未测**，暂时跟实测（带着）。
4. 网关补 `reasoning_loop_recovery` 等价护栏（Strata 的整段复读恢复：`LOOP_CHECK_EVERY 512`、`LOOP_COVERAGE 0.25`、`LOOP_HISTORY_WORDS 30000`）—— 我们的引擎没有这一层，agent 长跑时是该补的。
5. 200K 上下文：唯一已知路径是换社区 `CraneBW` 的 SM89 自编译（`-DNINFER_SM_COUNT=34`），未验。
6. 社区其他人方案的整合（你说下一阶段）—— 已备好素材：4,248 条评论 + 7 个竞品仓库，见 `reports/评论区与竞品项目-洞察.md（已删除，未入库）`。

## 8. 社区情报摘要（下一阶段用，不是现在的结论）

- **本机已是同卡最强档**：4,248 条评论里没有第二个 4060 Ti 8GB 报到 90+ decode。
- 社区 8 GB 账本（`5258MF/ninfer-rtx3060-27b` README-8GB:226-233）的拟合式 `reservation = 1,374,117,632 B + 27,336 B × kv-capacity` 与我们实测边际一致 ⇒ 交叉验证通过。
- 已否的社区"妙招"：`--lm-head-q4/q6`（PTQ1 不支持）、`--disk-kv-*`、`--use-alt-prefix-caching`、`--wddm-evictable-budget`、`--spec dflash2`、`--kv-dtype nvfp4`、`--vision`。
- 值得下一阶段试的只有一条：**CraneBW 的 SM89 自编译**（冲 200K 上下文）。
