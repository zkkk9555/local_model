# 上下文怎么用到极限：一页操作手册（2026-10-30）

机器：RTX 4060 Ti 8 GiB · 27B PTQ1（5.96 GiB）· NInfer KVMem 环模式

## 三个档位（互斥，一卡一实例）

| 档位 | 命令 | 池 | 可信上下文 | 速度 |
|---|---|---|---|---|
| 日常（默认） | `bash scripts/switch.sh ninfer` | 40,000 | 40K | decode 97–107 tok/s，70K prefill 1,000 tok/s 级 |
| 长文 | `bash scripts/switch.sh long72` | 72,000 | **70K（实测 8/8，96 s）** | 无 MTP，decode 约 55–65 tok/s |
| 极限长文 | `bash scripts/switch.sh long80` | 80,000 | 78K（起服后剩 137 MiB） | 同上 |
| 200K+ 单遍 | `bash scripts/switch.sh llama` | tiered KV | 262K | 首字以小时计 |

`long72` 起来的引擎 model id = **`bonsai27b-ptq1-nomtp-rk2v4-72k`**，DSH 里已加好同名条目（contextWindow 80,000 / maxTokens 8,192）。

## 超长文档（150K / 200K）——分片，不要单遍

```
bash scripts/switch.sh long72
python tools/longdoc.py --doc C:/path/doc.txt \
  --question "这份文档里出现过哪些形如「动物-四位数字」的校验码？按顺序全列" \
  --engine http://127.0.0.1:8091/v1 --model bonsai27b-ptq1-nomtp-rk2v4-72k \
  --shard-tokens 26000
```

实测：150K（151,805 tok）= 7 片 / **192.6 s** / 8 针全中；200K（202,586 tok）= 8 片 / **316 s** / 8 针全中。

代价 3–5 分钟，换来「每片都 ≤ 池 = 每片都可信」。单遍 200K 会给出「文档里 0 个校验码」这种自信假答案。

## 三条铁律

1. **prompt token ≤ 池**，超出就是不可信：只超 31% 就稳定丢 1 针（7/8），超 2.4× 剩 1/8，超 3.2× 全丢。
2. 起服脚本 `scripts/serve2.sh` 的 `NINFER_KV_RETRIEVE` 保持 **auto**（默认，不设）；设成写死值会把证据页从 500 页砍到 128 页。
3. 判断有没有超池只能看引擎 warning 或自己数 token；**不看 warning 不等于安全**（30 s 节流）。

## 顺手修正的两个旧认识

- 旧脚本写死 `NINFER_KV_RETRIEVE=8192`（=128 页证据）⇒ 现在 unset，引擎 AUTO 给 **500 页**（池的一半，上限被夹在 500）。
- `--spec mtp` 多吃 0.42 GiB ⇒ 40K 档能开 MTP，72K/80K 档必须关。

## 150K / 200K 定稿（2026-10-30 13:30，可重复 4 次）

分片注入已经从「命令行工具」升级成「常驻代理」，DSH 里可以直接选模型：

```bash
bash scripts/switch.sh long72     # 引擎：池 72,000、无 MTP、rk2v4-e8
bash scripts/longctx.sh start     # 代理：127.0.0.1:8086（估 token ≤ 池85% 直通，超过自动分片）
```

| 目标 | 片数 | 实测耗时 | 命中 | 复现次数 |
| --- | --- | --- | --- | --- |
| 150K | 7–8 | 134.9 / 159.5 s（longdoc）· 173.2 s（代理） | 8/8 | 3 次全过 |
| 200K | 9–11 | 211.4 / 211.7 / 211.4 s（longdoc）· 231.2 s（代理） | 8/8 | 4 次全过 |

- 代理回答开头会自己写「（超池分片注入：原文约 N token > 引擎池 72000，已切成 M 片…）」——**不伪装单次推理**。
- 分片工具 `tools/longdoc.py` 新增 `--answer-regex`（默认只留「名称-数字」形态，压掉数字堆砌）、`--pool-tokens`（任一片超池 → 退出码 3）。
- 200K 那三次 1/8 的旧读数**不是引擎问题**：fixture `doc-200k.txt` 只插了 1 个针，8 针版是 `tmp/exp/doc-200k8.txt`；再加上「模型只抄数字」被过滤丢掉，两处都已修。

**单遍仍然只有 88,618 token**（池 88,000 剩 33 MiB；池 96,000 拒启：`requires 1559880704 bytes, but only 1487929344 bytes available`）。
90K 以上没有第三条路：`--kv-dtype` 全表里 rk2v4-e8（0.84 MiB/页）已是最省，150K 需要 1,921 MiB KV + 6,103 MiB 权重 > 8,188 MiB。
