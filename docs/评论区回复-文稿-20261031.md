## 1. 主文稿（覆盖 80% 追问，一次贴完）

```text
统一回一下几位同卡的朋友，免得一条条说。我的配置：4060Ti 8G + 32G 内存 + Win11，模型 Bonsai2-27B PTQ1（5.96 GB），引擎 NInfer KVMem sm_89 预编译版，不用编译、不用装 CUDA Toolkit。

【速度】同一张卡上 40 和 110 都是真的，差在"让它写什么"。刚在同一台机器上量的（40K 档，温度 0）：
· 从 1 数到 400 = 110 tok/s（每个解码步一口气吐 4.5 个 token）
· 写 Python 脚本 = 75 tok/s（3.1 个）
· 写散文随笔 = 39 tok/s（1.6 个）
解码步频恒定在 24.5 步/秒——卡的"一步"就那个速度，MTP 投机解码命中率高的时候一步能出 4-5 个 token，写散文只出 1.6 个。所以谁报 100、谁报 40，多半是测的内容不一样，不是谁装错了。

【上下文】40K 不是"什么也干不了"：40,000 token 大约 = 6 万字符 = 100 页 PDF = 4000 行代码 = 3 小时录音转写。我拿 6 万字符的文档试过，让它把埋在段落中间的 3 条关键信息捞出来，3/3 全中，27 秒。

真正的坑是：prompt 一旦超过 KV 池，它会悄悄漏掉中间那一段，还给你 HTTP 200、看着完全正常的错答案。所以我这边分三档用：日常 40K（快）、长文档 72K（关 MTP，31 tok/s，单遍能读 8 万字）、15 万字以上直接分片注入（每片都不超池，逐片取证）。

【这张卡的硬上限】8 GB 显存里，池推到头是 88,000 token（起服后就剩 33 MiB），单遍 88,618 token 实测 8/8 全中。150K 单遍在 NInfer 上算术上不可能：权重 5.96 GiB + 150K×0.84 MiB 的 KV = 9.4 GB > 8.19 GB。想吃更大窗口只能走 llama.cpp 的 host-tail 分页（262K 窗口能起，150K 单遍实测 8/8，但首读 268 秒、生成 12.6 tok/s）。

【启动参数】40K 日常档（可直接抄）：
池 40,000 / --kv-dtype rk2v4-e8 / --host-kv-mib 6144 / NINFER_KV_WINDOW 16384
--spec mtp --draft-tokens 4 --mtp-attention-window 8 / --prefill-chunk 1536
--cuda-graph-allowance-mib 16 / --ngram-draft-tokens 0 / --device-state-slots 0
--max-concurrency 1 / --max-shared-prefixes 0 / --max-context 262144 / --default-max-tokens 8192
环境：NINFER_HOST_PAGEABLE=1、NINFER_KV_REUSE_HOSTBACKED=1、NINFER_TERNARY_PTQ1_FAST=1，NINFER_KV_RETRIEVE 留空（留空引擎才会自动给"池的一半"当证据预算，写死 8192 只有 128 页）。

【三个最容易踩的】① 一张卡只能起一个引擎实例，同时起两个会互相抢显存然后进程消失；② 别开思考/reasoning，速度砍一半；③ KV 用 bf16 的话池只能开到 1 万左右，rk2v4-e8 才能到 4 万。

我这套的脚本、参数、每档实测读数、以及"超池为什么会静默错"的证据都整理在 GitHub 上了：github.com/zkkk9555/local_model  （只放脚本和报告，模型和引擎太大没传，里面写了从哪下、校验值多少）
```

## 2. 短版（对方只问了一个问题就用这个）

**如果问「为什么我是 40 tok/s」**

```text
40 是正常的——写散文、自由发挥就是 38-41。我从 1 数到 400 才有 110，写代码 75。
差别在 MTP 投机解码：解码步频恒定 24.5 步/秒，每步能中 4.5 个草稿 token 就是 110，只中 1.6 个就是 39。
先对三处：① 有没有 --spec mtp --draft-tokens 4；② KV 是不是 rk2v4-e8（bf16 池只能开 1 万）；③ 有没有开思考模式（开着速度砍一半）。
参数贴出来我帮你对。
```

**如果问「40K 够用吗 / 你平时怎么用」**

```text
40K ≈ 6 万字符 ≈ 100 页 PDF ≈ 4000 行代码，够读一份长文档或一个中型项目。
我分三档：日常 40K（110 tok/s）、长文档 72K（关 MTP，31 tok/s，能读 8 万字）、15 万字以上走分片注入（每片不超池，逐片取证再合成，150K 大约 135 秒）。
关键不是能塞多少，而是**塞超了它会静默答错**——超池的请求 HTTP 还是 200，答案看着正常，中间那一段就是没了。
```

**如果问「用什么引擎 / 要不要编译」**

```text
不用编译。作者发的是预编译 exe（按显卡架构分：30 系 sm_86、40 系 sm_89、50 系 sm_120a），
配 9 个 DLL 就能跑：CUDA 运行时三个（cudart/cublas/cublasLt 13）+ FFmpeg 五个 + libcurl。
不用装 CUDA Toolkit，也不用 VS Build Tools。注意路径必须纯英文、不能有空格和中文。
```
