## 1. 三个问题，三句话

1. **现役 NInfer 和 Strata 谁更好：NInfer 全面胜出，不是略胜，是一个数量级** —— 上下文 40,000 vs 1,024（39×）、prefill 1,001 vs 120.9 tok/s（8.3×）、decode 107 vs 42.1 tok/s（2.5×）。Strata 的 125B 档（Gyro-S）能把上下文开到 32,768，但 decode 掉到 19–24 tok/s、每轮读盘上百 GB，只能当**备胎**。
2. **Windows GPU 解锁对首字有没有用：NO-GO** —— 被钳的 A16 通路只占 prefill 时间 36.4%，解锁理论上限 **×1.163**，折到首字只省 **1.0 s @8K / 3.3 s @24K / 5.4 s @37K**，decode 与显存 **+0**；代价是每次冷启动插 U 盘过预驱动事务 + 整机变砖风险（同类组合已出现 Windows Code 12 / 引导黑屏）。
3. **各自极限**：NInfer 已在本机极限档（池 40,000 / `rk2v4-e8` / MTP draft4 / CUDA Graph，峰值 7,459 MiB，余 729）；Strata 极限 = 1,024 cell @ q36（42 tok/s）或 32,768 @ Gyro-S（20–24 tok/s）。两条都写在 `docs/两条路终极对照-20261030.md`。

## 5. 全网第三波搜集捞到的三条真增量

1. **8G 官方口径出现了**：KVMem 作者自己的 8G 推荐是 budget **36,864** + gen 4,096、KV **NVFP4**、MTP 3 draft、prefill 256、并发 1、CUDA Graph 留 256 MiB；5050 Laptop 8G 实测 36,669 输入满生成 4,096 → **22 t/s**、峰值 6,944 MiB。我们的 `--kv-capacity 40000` / `rk2v4-e8` 正压这条线 ⇒ **继续加池不是正确方向，该换的是 KV 精度（NVFP4）与草稿机制（DFlash2）**。
2. **NInfer 原生吃三元权重后单路能到 130 tok/s**（B 站沈三殊 383 赞：「把 baoshai27b 转成 ninfer 格式 + 拼三元矩阵逆量化算子，单路 130、两路 230」）。我们 97–107 tok/s 仍有空间，瓶颈不在权重格式。**工程件本机未取得，属待验证项**。
3. **200K 的算术被修正**：设备常驻需 3,200 页 × 0.84 MiB = **2.63 GiB**、可用只 1.15 GiB ⇒ 设备顶到 **约 87.6K**；宿主页只需 204,800 × 25.12 KiB = **5.02 GiB**，现配 `--host-kv-mib 6144` 其实够到 **244K**。⇒ 200K 不是算术不可能，卡在「池外回读是否只可信一次」（NInfer issue #12 是显式崩，我们是静默错）。

另外两件可立刻试的小优化：**MTP 头 Q4 化**（把 27B 文件从 5.96 → 5.76/5.87 GiB，能多 1–2K 池，ik_llama.cpp `--mtp-requantize-output-tensor`，PR #1809）；**DFlash2 草稿头缩词表**（草稿头少读 2.5–3× 字节，作者 Mac M4 +3.8% tok/s，称为无损）。

负面结论（省得再找）：262K 没有更高档；2026-09 之后没有新的「8 GB 跑 30B 级」引擎；8 GB 卡上找不到任何 100K+ 且速度可用的案例（100K+ 全在 11–12 GB 且伴随腰斩）；魔搭底座比 HF 旧且慢，独家价值只在中文打包。
