# Strata 与我们的部署：8 GB 上到底能跑到什么程度（2026-10-30）

来源：BV1PwHs6vEiY（Strata 问答，503 段字幕）、BV1HMHw6wETo（32G 内存 + 8G 显存跑 85G 文件，493 段字幕）、两视频各 40 条评论；字幕存 `tmp/bili_strata_A.txt` / `tmp/bili_strata_B.txt`。本机数字全部来自我们自己这两天的实测。

## 一句话结论

两条视频讲的不是「同一个模型换个引擎」，而是**换了模型的架构**：

- **我们的路线（NInfer + Bonsai 27B ternary）**：稠密模型，27B 权重每个 token 全部参与 ⇒ **必须整份驻留显存**。8 GB 卡上能给出的最好状态是 **97–98 tok/s、真实上下文 40,000**。
- **视频里的路线（Strata + Qwen3.8-Flash-Next 125B MoE）**：MoE 模型每 token 只激活一小部分专家（约 12B 级）⇒ 专家可以放内存、按需调入 ⇒ 8 GB 显存也能跑 125B，**上下文 128K–256K**，代价是速度掉到 **20–40 tok/s**。

所以「8G 能不能 200K」的正确答案是：**用 27B 稠密模型不能（硬上限 40K，极限约 95K 但慢到 32 tok/s）；用 MoE + Strata 能，但这等于换模型、换引擎、再下 85–105 GB 权重。**

## 本机实测（NInfer + Bonsai 27B ternary PTQ1，RTX 4060 Ti 8G / 7800X3D / 32 GB DDR5-6000）

| 档 | 池（真实上下文） | decode | prefill | 峰值显存 | 结论 |
|---|---|---|---|---|---|
| 现役 legacy 40k | 40,000 | 97–98 tok/s（计数题）/ 45.7（散文） | 963 tok/s @37K | 7,469 MiB | **当前最优平衡** |
| 32k | 32,000 | 96–98 | 743–960 | 7,357 MiB | 已被 40k 取代 |
| 52k | 52,000 | — | 崩到 ~180 tok/s | 7,573 MiB | 不可用（疑似 WDDM 换页） |
| 56k+ | — | — | — | 拒启 | `runtime reservation requires 1.09 GB, only 1.037 GB available` |
| 超池 82K | 逻辑 262,144 / 池 32,000 | 35.3 | 743 | 7,357 MiB | 双针全对，但引擎打 unverified 警告 |

固定开销 ≈ 6.95 GiB（权重 5.94 GiB + 运行时 0.4–1.0 GiB）。**8,188 − 6,950 = 1,238 MiB ÷ 0.836 MiB/页 ≈ 1,480 页 ≈ 94,700 token 是这套稠密模型的物理天花板**（还要关掉 MTP，速度掉到 32 tok/s）。200K 需要 2.6 GiB KV，装不进去。

## 为什么我们「没把硬件用满」（这是个设计事实，不是配置失误）

| 资源 | 我们（稠密 27B / NInfer） | Strata（125B MoE） |
|---|---|---|
| 显存 | 7,469 / 8,188 MiB = **91%**，已到顶 | ~95%，已到顶 |
| 内存 | 引擎 private **14.8 GiB**（6 GB host KV 钉子 + 权重暂存） | 70/96 GB（专家常驻） |
| CPU | ~0%（只做分词与采样） | 70%（要搬专家、算部分层） |
| 硬盘 | 只在加载时读 | 内存不够时按需读专家（NVMe 才勉强） |

稠密模型的每一次矩阵乘都必须过 GPU；把权重放内存让 CPU 算，PCIe 4.0 x8 每秒只搬 16 GB，而 27B 每 token 要走 54 GB 权重 ⇒ 理论 0.3 tok/s。**CPU 和硬盘对我们这条路线天生无从下手**，这是稠密 vs MoE 的结构差异，不是我们没调好。

## 三条能拿到长上下文的路，各有代价

1. **保持 NInfer，超池环模式**：`--max-context 262144` + 池 40,000，理论上能塞 200K 文档。代价：引擎明说超池区「middle 会静默丢失、HTTP 200 + 看似合理的错答案」。我们 82K 双针测出 2/2 命中（正控强），但**这属于未验证区**，生产必须走 `chat_gateway.py` 分片注入（L2s，每片 ≤ 池）。
2. **换 Strata + Qwen3.8-Flash-Next IQ3_S**：真 128K，256K 可用，速度 20–40 tok/s。代价：再下 ~85 GB 权重（D: 还有 240 GB，放得下）、固定内存 27 GB（我们 31.1 GiB 要关掉大部分软件）、和 NInfer **不能同时驻留**（8 GB 只够一套）。
3. **两者并存切换**：日常对话/写代码用 NInfer 40K（97 tok/s）；只在读长文档、要模型能力时切 Strata（27 tok/s，128K）。用启动脚本切 profile，同一张卡一次只起一个。

## 建议

- **现在：不动主力**。NInfer 40K 是这颗卡上稠密模型的极限档（91% 显存、97 tok/s、37K 提示 963 tok/s prefill），已经验过 5 档池、20+ 组开关。
- **想要 200K 上下文或更强模型：装 Strata 那一套**，按视频 B 的参数（固定 27 GB 内存、上下文 262144、KV k8v4），预期 128K 下 20–40 tok/s。这是真实可达的，不是玄学——前提是接受速度只有现在的 1/3。
- **不建议**继续在 8 GB 上榨稠密模型的上下文：52K 已崩、56K 拒启，剩下的空间只有噪声级收益。
