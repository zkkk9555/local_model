# AI Agent 能不能「看」B 站视频？——两条现成路线的解剖与本机落地方案

> 调研对象：`repos/dsh-bili-scroll`（v2.3.1）、`repos/dsh-video-storyboard`（v0.4.4）
> 本机事实：Windows + DSH Desktop **0.2.1-rc.3**（Electron 桌面版，profile = `desktop`），默认模型 `wb/deepseek-v4.1-flash`，其声明输入为 `[text, image]`。
> 调研方式：**只读代码 + 联网调研**。按用户要求，**没有下载任何视频、没有跑任何转写/抽帧流水线**。
> 网络：本机直连与代理 `http://127.0.0.1:7897` 均可用；本轮 GitHub API / raw.githubusercontent / npm registry 全部走代理，PyPI 未访问（无需）。

---

## 0. 结论速览

**能看，但必须把「看」拆成两件事**：

| 你要的东西 | 该走的通路 | 本质 |
|---|---|---|
| UP 主**讲了什么**（口播、教程、观点） | **B 站字幕轨**（`ai-zh`/`zh-CN`）→ 没有则 **ASR 转写** | 文本，不需要视觉模型 |
| 视频**长什么样**（演示、代码屏、PPT、图表） | **抽帧 → 宫格图 → 交给多模态模型** | 图，每张宫格固定 384 token |
| 视频**热不热/大家怎么说** | 公开 API：播放/点赞/评论/弹幕/搜索 | 结构化 JSON |

三条硬事实：

1. **B 站九成以上有字幕轨（含 AI 字幕），抓下来比任何本地转写都快、都准**，代价是**必须登录态（SESSDATA）**。这一点被三份互相独立的代码同时证实（见 §9 证据 3/4/5）。
2. **两个仓库正好各占一头**：`bili-scroll` 是「信息流 + 发现 + 粗筛」（每天刷一轮、读字幕判断值不值得看）；`video-storyboard` 是「单视频精读」（分镜 + 关键帧 + 逐格台词），它不是转写工具，转写只是它的配件。
3. **本机的图片通路已经实测打通**：我用 `read_image` 读了 `repos/dsh-video-storyboard/docs/demo.png`（1009×623），能准确说出 9 宫格里每一格的编号、彩条/渐变/噪点内容和底部青色音频包络条。⇒ 「宫格图方案」在这台机器上**可行，不需要额外的视觉 API key**（与 `dsh-video-lens` 那条要外部 VLM key 的路完全不同）。

## 2. 两个项目到底怎么实现「看视频」

### 2.1 dsh-bili-scroll（v2.3.1）：四条通路，主打「读字幕」

它的核心不是「理解视频」，而是「**替你刷 B 站并判断值不值得看**」。四条通路按优先级：

**通路 A —— B 站字幕轨（首选，零识别成本）**
- 入口 `bili_subtitle(bvid)`：`vendor/bilibili-mcp/mcp_server.py:520`
- 登录凭据构造 `video.Video(bvid=..., credential=cred)`：`:532` → `get_info()` 取 `cid`：`:534`
- 取字幕列表 `v.get_subtitle(cid=cid)`：`:542`；语言优先级 `ai-zh` → `zh-CN` → `zh`：`:551`
- 拿到 `subtitle_url` 后**直接 HTTP GET 那个 JSON**，把 `body[].content` 拼成全文：`:559-575`
- 无字幕直接返回「该视频没有字幕」：`:546`（不降级、不猜）
- ⇒ **这是「把视频变成文本」最便宜的一条路：一次 HTTP，几百毫秒，零 GPU**。

**通路 B —— 本地 ASR（可选组件，需单独安装）**
- MCP 侧：`bili_transcribe` `:1523`、`bili_transcribe_start` `:1566`、`bili_transcribe_result` `:1597`（异步 job，超时 900s，轮询等待 25s）
- 实际执行：`lib/asr.py` —— yt-dlp 拉音频 `bestaudio/best`、带 `Referer: bilibili`（`:57-81`）；`faster_whisper.WhisperModel(model, device='cpu', compute_type='int8')`（`:109-111`），默认 `small`（`:88`），`vad_filter=True`（`:116`）
- 模型来源：`HF_ENDPOINT=https://hf-mirror.com`（`:43`）、`HF_HOME` 落插件家目录 `.hf-cache`（`:45`）、`HF_HUB_DISABLE_XET=1`（`:47`）⇒ **国内可下、不污染全局缓存**
- 安装器：`index.js:2330 installAsr` → `uv venv .venv-asr`（`:2347`）→ 装 `faster-whisper / yt-dlp / av>=12,<17`（`:2387-2391`，**av 必须 <17**）→ 三个 PyPI 镜像轮换（清华/USTC/阿里，`:2390`）→ 预下模型（`:2405`）
- ⇒ **纯 CPU int8，不需要显卡**；代价是 small 模型的中文准确率一般（见 §3.2）。

**通路 C —— 抽帧看画面，但用的是 B 站自带故事板（不下载视频、不用 ffmpeg）**
- `bili_frames(bvid, num=3, at=None)`：`:1813` → `v.get_video_snapshot(cid, json_index=True, pvideo=False)`：`:1852`
- 拿拼图 URL + 时间戳数组 `_snapshot_entries`：`:1743`；`index` 为空时用 `pvdata`（大端 uint16）兜底：`:1766`
- PIL `_crop_tile` 裁出一格 480×270：`:1794`，作为 MCP `ImageContent` 返回：`:1919`
- 限制：**只覆盖第 1P**；`index` 约 25% 偶发为空（`:1846` 注释）；值班模式下每轮最多对 3 条视频抽帧、默认 3 帧（`prompts/duty.md:171`）
- ⇒ 这是**零依赖的「瞄一眼」**：没有 ffmpeg 也能拿到 3 张 480×270 的图。分辨率低，只够判断「是不是代码屏/有没有 PPT」。

**通路 D —— 公开 API 元数据（真正的「稿件信息」层）**
`bili_video_info :610`（播放/点赞/收藏，`:638`）、`bili_comments :447`、`bili_danmaku :582`（取 100 条热弹幕）、`bili_search :396`、`bili_cover :1667`（512px 封面）、`bili_user_videos :1032`（按 UID 列 UP 主视频，`pn/ps=30`）、`bili_favorite_lists :1080` / `bili_favorite_content :1113`（收藏夹批量）、`bili_recommend :1962`（首页推荐流，需登录）、`bili_hot_videos :862` / `bili_rank :934` / `bili_weekly_hot :913`。

**还有一个被低估的批量入口**：`bili_crawl(keyword, max_videos=5, comments_per_video=20, get_subtitles=True)` `:714-772` —— 搜索关键词 → 逐个视频抓**评论 + 字幕全文**，每个视频 `sleep(1)` 限速（`:772`）。这就是「几十个视频」的现成批量原语。

**它的定位证据**：`prompts/duty.md:107-110` 每轮流程=「读字幕原文再判断」；`:137-139` 写「值得看」必须读过字幕或看过画面；`:146-174` 有一整节「什么时候该看画面」；`:116` 一轮最多排 1 条转写；`:38-40` 空字幕=没有语音，不是故障。工具白名单在 `index.js:1325-1341`（值班模式只放行 8 个只读工具 + 转写三件套 + 条件性的评论工具）。

### 2.2 dsh-video-storyboard（v0.4.4）：三条通路，主打「画面」

它解决的问题是「**文本模型的 token 账单**」：把 9–16 帧打进**一张宫格图**（编号烧进像素），一张图固定 ~384 token，而逐帧传要 3072–6144（`README.zh.md:13-14`、`:143-149`）。工具：`video_storyboard` / `video_zoom` / `video_probe` / `video_locate` / `video_watch`（`src/tool-spec.js:14-17`、`:475`）。

**通路 A —— 站点字幕轨（首选）**
- `src/subtitles.js:51 fetchRemoteSubtitles({url, cookies})` → 调 yt-dlp `--skip-download --write-subs --write-auto-subs --sub-format srt --sub-langs zh-Hans,zh-CN,zh,ai-zh,en,...`（`:90-97`）→ `asr.js:156 parseSrt`
- `:6-8` 注释直接写明：「**B 站字幕是单独轨道，下载下来的 mp4 里通常没有**」（这就是为什么它不依赖「容器内嵌字幕」）
- `:8-10` + `:103`：yt-dlp 报 `Subtitles are only available when logged in` → 标记 `reason: needs-login`，**不静默降级**
- `checkBiliLogin` `:134`：直接打 `https://api.bilibili.com/x/web-interface/nav`，凭 `SESSDATA / bili_jct / DedeUserID / buvid3`（`:144`）

**通路 B —— ASR 三级降级**
- `src/asr.js:1-10` 注释即设计：① 容器内嵌字幕轨 `extractSubtitleTrack :170`（`ffmpeg -map 0:s:0 -f srt`）② OpenAI 兼容 `/audio/transcriptions` ③ 都没有就返回 `null`，**不让整体失败**
- 默认端点 `https://api.siliconflow.cn/v1`、模型 `FunAudioLLM/SenseVoiceSmall`（`:116-117`）；配置优先级 env(`DSH_ASR_BASE_URL/MODEL/KEY`) > `$DSH_HOME/asr.json` > 默认（`:108-131`）；**本机 127.0.0.1 不要求 key**（`isLoopback :69`、`needsCloudKey :86`）
- 切片 ≤45s，切点落在静音中点（`README.zh.md:67`）——避免把一句话切断导致时间码漂移

**通路 C —— 抽帧 / 分镜（全靠 ffmpeg 外部进程）**
- 二进制发现顺序：`DSH_HOME/tools/ffmpeg/bin` → DSH 安装根 `tools/ffmpeg/bin` → `PATH`（`src/binaries.js:68 DEFAULT_FFMPEG`）
- 切点检测：`src/scan.js` 用 ffmpeg 缩到 **64×36 rawvideo** 做 HSV 三通道差；**刻意不用 `ffmpeg scdet`**，因为它对「同亮度换色」的硬切失明（`:4-7`）
- 取最锐帧：`src/sheet.js:353 extractFrameRaw`，每段 3 候选帧比 **Laplacian 方差**
- 零模型音频分析：`src/audio.js` 用 `ebur128` + `silencedetect` 量响度/静音（`:2`、`:43/:74`）
- 取流：`src/fetch.js:172 discoverYtdlp()`（真跑 `--version` 验证）；扫描用 **360P 全片落盘**（`:471-474` `scanHeight=360`、`zoomHeight=1080`），带 `--add-header Referer:https://www.bilibili.com/`（`:571`）；`video_zoom` 走 1080P 直链**不落盘**
- **cookies 是硬需求**：同一条视频匿名只有 480P，登录才 1080P，且高档格式压根不在匿名格式列表里（`fetch.js:9-10`、`:653`）。来源 = `DSH_VIDEO_COOKIES`（Netscape cookies.txt）或 `~/.dsh/video.json` 的 `cookies` 键；`fetch.js:298` 明确劝退 `--cookies-from-browser`（Chrome 加密读不出），**要用浏览器扩展导出**
- 长片预算：每格台词封顶 `detail low 60 / med 120 / high 400` 字符；`cellRange + textOnly` 翻页**不重出图**（`README.zh.md:98-112`）；2h35m 的片子 64 格清单 75KB 会超宿主单次工具结果上限

**旁支**：`video_watch`（`src/watch.js` / `watch-loop.js` / `watch_smtc.py`）是「跟着**正在播放**的视频实时看」（Windows SMTC 媒体会话），和「离线批量提炼」不是同一条路，别混用。

**它的工程细节值得借鉴**：转写和扫描**并行**跑（`src/pipeline.js:189-191` 注释：21 分钟教程实测「扫描 133s、转写 58s、串行 202s」，并行后只等较慢的那个）；`src/pipeline.js:220-242` 的降级判定分「有字幕但要登录 / 压根没配 key / 跑了但没听到话」三种，避免把「没配」说成「没人说话」。

### 2.3 正面差异（一句话版）

| 维度 | dsh-bili-scroll | dsh-video-storyboard |
|---|---|---|
| 一句话定位 | **替你刷 B 站**：发现 → 粗筛 → 写日报 | **陪你看一条片**：分镜 + 关键帧 + 逐格台词 |
| 输入 | BV 号 / 关键词 / 推荐流 / 收藏夹 | 本地文件或 http(s) 链接（含 B 站） |
| 输出 | Markdown 日报（`out/<日期>.md`）+ 可选评论 @你 | 宫格图 PNG + 结构化清单（时间轴 + 台词 + 音频包络） |
| 主要依赖 | Python 3.10+/uv；ASR 可选（faster-whisper） | **ffmpeg/ffprobe 必须**；yt-dlp（贴链接时）；ASR 可选 |
| 需要登录 | 是（扫码，`bili_credential.json`） | 字幕/高清需要 cookies；纯画面 480P 可不登录 |
| 视觉能力 | B 站故事板 3×480×270（零依赖） | 9–16 格宫格，360P 扫描 / 1080P 单帧 |
| 批量能力 | 强（`bili_crawl` / 收藏夹 / UP 主列表） | 弱（一条一条来；靠 `--batch` 分窗） |
| 对「讲了什么」的贡献 | **直接**（字幕全文） | **间接**（字幕轨 + 分格台词） |
| 对「长什么样」的贡献 | 弱（3 张低清帧） | **强**（分镜 + 关键帧 + 屏幕文字） |

## 3. 到底能不能拿到内容？

### 3.1 按内容类型选路（这是全篇最重要的一张表）

| 视频类型 | 最有效通路 | 为什么 | 还需要什么 |
|---|---|---|---|
| 口播 / 访谈 / 技术讲解（有字幕） | **B 站字幕轨** | 平台已经识别过一遍，比本地 small 模型准；一次 HTTP 几百毫秒 | 登录 cookie |
| 口播 / 教程（**无**字幕） | **本地 funasr > faster-whisper > 云 ASR** | funasr（Paraformer-zh）中文带标点、带 VAD，公认中文最优；云端最省事但要把音频发出去 | 装一次（约 1GB）/ 或有 API key |
| 代码演示 / 软件操作 / PPT | 抽帧宫格 **+** 字幕 | 画面只有「哪一步在点什么」，讲解在音频里；两者缺一不可 | ffmpeg + 多模态模型 |
| 纯音乐 / 无语音 | 抽帧 + 封面 + 简介 | 字幕为空是正常现象（`prompts/duty.md:38-40`），别当故障 | — |
| 多 P / 合集 | 逐 P 取 `cid` 再取字幕 | 故事板只覆盖第 1P（`mcp_server.py` 注释 `:1846` 一带） | 遍历 P 列表 |

### 3.2 准确率体感（**估算，非本机实测**；用于选型排序）

| 通路 | 中文技术口播 体感准确率 | 典型错法 |
|---|---|---|
| B 站官方 / AI 字幕 | **90–95%** | 英文术语、型号、人名（`Transformer`→`穿丝佛魔`这类） |
| funasr Paraformer-zh（本地） | 85–92% | 长句断句、专有名词 |
| faster-whisper `large-v3`（本地） | 88–93% | 慢；术语仍会错 |
| faster-whisper `small` CPU int8（bili-scroll 默认） | **75–85%** | 术语错得明显，短句合并 |
| SenseVoice-Small（云） | 85–92% | 快、带情感/事件标签，但按分钟计费 |
| 宫格 9–12 帧视觉理解 | 对「讲了什么」贡献 < 20% | 只能给「有没有代码屏/几段结构/大致在演示什么」 |

⇒ **对「UP 主讲了什么」这类需求，答案很干脆：字幕优先，ASR 兜底，视觉只用来补「画面里才有的信息」**。反过来，只看画面去猜讲解内容，是最贵的错路。

### 3.3 硬依赖清单（真的绕不过去的）

| 依赖 | 谁需要 | 能不能绕 | 说明 |
|---|---|---|---|
| **B 站登录 cookie（SESSDATA）** | 两者都 | 绕不过（想拿字幕/高清） | 匿名拿不到 `ai-zh` 字幕轨：`subtitles.js:8-10`、yt-dlp `bilibili.py:267-269`、VideoNote 手册 `:235` 三方一致 |
| **ffmpeg / ffprobe** | storyboard、video-lens、VideoNote | 绕不过（要抽帧/切片） | bili-scroll 的 `bili_frames` 是唯一「不用 ffmpeg 也能看图」的例外 |
| **yt-dlp** | storyboard 贴链接时、bili-scroll ASR | 可绕（本地文件/预下载） | `fetch.js:172` 会真跑 `--version` 验证，装了坏的会明确报错 |
| **ASR 引擎** | 只有「无字幕视频」才需要 | 可绕（跳过或换视频） | bili-scroll 没装转写时会把无字幕视频**跳过**并在报告里写「因无字幕跳过 N 条」 |
| **本地显卡** | 谁都不需要 | — | faster-whisper 走 ctranslate2，CPU/int8 可用；有 CUDA 才加速（需 cuBLAS 12/Lt 12，`VideoNote 手册:248`）。**「必须本地显卡跑 whisper」是个误解** |
| **云 API key** | `dsh-video-lens` 需要（默认 SiliconFlow VLM+ASR）；storyboard/VideoNote **默认不需要** | 可绕 | storyboard 的宫格图直接交给宿主模型看；本机已实测可读图 |

### 3.4 已知坑（都来自代码/README，不是猜的）

- **桌面版没有 `web` profile**：本机只有 `~/.dsh/profiles/desktop`，而 bili-scroll README 的安装命令写的是 `dsh plugin --profile web add ...`。更硬的一条：`repos/dsh-video-storyboard/scripts/install-dev.mjs:9-10` 明确说 **desktop profile 由 Electron 应用独占管理，`dsh plugin --profile desktop ...` 会被拒绝**（`managed exclusively by the Electron application`）。
- **npm 上的 bili-scroll 是旧版 0.1.7**，仓库最新 2.3.1，README 让你从 Release 的 tgz 装。
- **bili-scroll 的 ASR 是两段式**：只打开开关不够，还得点「装转写依赖」（`README.md` 第 4 条坑）。
- **storyboard 的 1080P 依赖 cookie**：匿名 480P；`zoom` 想拿 1080P 直链必须有 cookies。
- **故事板抽帧有 25% 概率没有时间索引**（`mcp_server.py:1846` 注释）。
- **长片清单会超工具结果上限**（2h35m/64 格 ≈ 75KB），要靠 `cellRange + textOnly` 翻页。

## 4. 操作步骤（最小可行路径）

> 原则：**先验证「字幕能不能拿到」再谈装插件**。80% 的需求在第 1 步就结束了。
> 所有命令都在 `C:/Users/Administrator/Documents/deepseek-harness/default-workspace` 下用 bash（`ops_bash`）执行。

## 5. 定位差异 & 「把一个 UP 主几十个视频提炼成要点」谁更合适

**结论：单靠任何一个都不合适，但 bili-scroll 是「入口」，storyboard 是「放大镜」。**

- bili-scroll 适合：一次性把 UP 主的视频**列表化**（`bili_user_videos :1032` / 收藏夹 `:1080`）、拿**字幕全文**（`:520`）、拿评论热度做优先级排序；它甚至内置了 `bili_crawl :714` 这种「关键词 → N 个视频的字幕+评论」的批处理。
- 但它的产品形态是「**每天刷一轮、挑几条、写日报**」，不是「把 30 个视频各写 800 字要点」。日报模板（`prompts/duty.md`）也是为「值得看/不值得看」设计的。
- storyboard 适合：对**已经筛出来的关键视频**做一次深读——分镜告诉你结构（几段、哪里切换主题），逐格台词告诉你细节，宫格图告诉你「屏幕上是代码还是 PPT」。
- 它的短板恰好是批量的反面：一条一条来、每条都要下载 360P 全片扫描、长片清单会超限。

### 推荐流水线（6 步，可脚本化）

1. **列表化**：`bili_user_videos(uid)` 或 `bili_favorite_content(media_id)` → 得到 N 个 BV + 时长 + 播放量。
2. **排序**：按播放/评论/时长筛掉 <3 分钟和纯切片，优先级 = 播放 × 评论/时长。
3. **取文本**：逐个 `bili_subtitle(bvid)`；成功的直接存 `raw/<bvid>.txt`（一次 HTTP，1 秒/个）。
4. **补漏**：无字幕的才排转写（funasr 或 faster-whisper medium），**一轮最多 1–2 条**，限速 `sleep(2)`。
5. **分层提炼**：每 3–5 个视频做一次局部摘要（贴在 `notes/<主题>.md`），最后再对局部摘要做一次全局提炼 —— 不要一次性把 30 篇字幕塞进一次调用（30 分钟口播 ≈ 8k–10k token，30 个视频就是 25 万 token 级别）。
6. **补画面**：只对「字幕里出现『看这里/这个按钮/这段代码』」的视频跑一次 `--text` 之外的宫格，用 `read_image` 看一眼。

限速：`bili_crawl` 自己是 `sleep(1)`（`mcp_server.py:772`）；批量抓字幕建议 **≥1.5s/请求**，否则容易 412 风控。

## 7. 风险与合规

| 风险 | 具体表现 | 缓解 |
|---|---|---|
| **平台条款** | 批量抓取字幕/下载视频违反 B 站用户协议；2026-01 有维护者因整理非公开接口收律师函（bilibili-API-collect 关停） | 仅个人学习、低频、不传播、不商用；不要做「接口文档站」 |

## 8. 推荐路径（三档，按你的耐心选）

**档 1｜15 分钟，只想知道「讲了什么」**：路线 A 的 A1+A2+A3+A4。装 ffmpeg + yt-dlp + 导 cookies，用 storyboard 的 CLI 出 `--text` 清单。**不装任何插件**，不碰 DSH profile。

**档 3｜半天，要「每天自动刷」**：再加装 bili-scroll（设置页「装依赖」+ 扫码 + 「现在跑一轮」），让它每天出日报；你只在日报里挑 2–3 条，再用 storyboard 深读。**注意桌面版别开「自动跑」**。

**如果只记一句话**：先证明「这条视频有字幕、且我能拿到」——这一步 5 分钟、零风险；拿不到再谈 ASR，最后才谈视觉。
