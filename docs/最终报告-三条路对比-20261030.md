# 三条路对比与最终结论（2026-10-30 实测）

> 本机：RTX 4060 Ti 8 GB（sm_89）/ Ryzen 7 7800X3D / 31.1 GB DDR5-6000 / Win11 26100。
> 所有数字都是本机当天实测，日志在 `C:/Project/local_model/logs/`，报告在 `reports/`。

## 0. 一页结论

| 问题 | 答案 |
|---|---|
| 现在跑什么 | NInfer KVMem + Bonsai 27B ternary PTQ1，40K 池，**decode 107.3（计数）/ 41.5（散文）tok/s**，prefill **1,001 tok/s @37K**，峰值 **7,459 / 8,188 MiB** |
| GPU 解锁值不值 | **不刷**。decode 0 收益、显存 0 收益、首字上限 **+16.3%**（37K 省 5.4 s）。代价是每次开机过固件事务 + 易失 + 驱动更新重刷 + 重启中断服务 |
| Strata 值不值 | **本机起不来**。35B-A3B 档 28 次尝试全部 EngineDied，最省也**缺 242 MiB**；125B 档只能等 Gyro-S low-RAM（专家走 SSD 读），社区同档 15–21 tok/s |
| 8G 能不能 200K | 能**读**不能**反复问**：分片法 8/8 全对、316 s、可重复；单发超池只有进程内第一次可信 |

## 1. 现役 NInfer：今天刚换成 MAX16 档

### 1.1 参数（`scripts/serve2.sh` 的 `PROFILE=max`）

```
--kv-capacity 40000 --kv-dtype rk2v4-e8 --host-kv-mib 6144 --prefill-chunk 1536
--cuda-graph-allowance-mib 16 --ngram-draft-tokens 0 --device-state-slots 0
--gdn-state-fp16 --spec mtp --draft-tokens 4 --mtp-attention-window 8
--max-context 262144 --max-concurrency 1 --max-shared-prefixes 0 --derive-session-keys
env: NINFER_KV_WINDOW=16384 NINFER_KV_RETRIEVE=8192 NINFER_HOST_PAGEABLE=1
     NINFER_KV_REUSE_HOSTBACKED=1 NINFER_TERNARY_PTQ1_FAST=1
```

### 1.2 相对上一档（`ctx40`，无 CUDA Graph）的净收益

| 指标 | ctx40 | **MAX16（现役）** | 变化 |
|---|---|---|---|
| decode 计数 | 104.1 | **107.3** | +3.1% |
| decode 散文 | 39.9 | **41.5** | +4.0% |
| prefill 8k | 1,091.2 | **1,108.5** | +1.6% |
| prefill 37k | 969.0 | **1,001.3** | +3.3% |
| TTFT @37k | 37.9 s | **36.7 s** | −1.20 s |
| 峰值显存 | 7,307 | 7,459 | +152 MiB（整卡余 729） |

机理：`reservation = 固定底座 817.6 MiB + graph allowance`，本机可用只有 **989.0 MiB**，引擎自动算的 allowance 是 444–588 MiB
⇒ 这才是 8G 上「MTP 与 CUDA Graph 不能共存」的真正原因（不是池、不是 draft）。
用 `--ngram-draft-tokens 0` 把真实图用量从 106 MiB 压到 ≤16 MiB，allowance 给 16 就同时开了 CG + MTP。
**注意**：allowance 128 + chunk 1536 数学上不可共存（差 142 MiB），要 128 的余量必须把 chunk 退回 1024（那是备选 `FINAL` 档：decode 107.9、峰值 7,291）。

### 1.3 8G 的真实天花板（三条都是实测出来的）

- **prefill 被自己的 INT8 通路救着**：`--no-prefill-a8` 一关，8k prefill 从 1,099 → **396.5 tok/s**（慢 2.77×）⇒ A8 段占 prefill 时间 **63.6%**。
- **decode 卡在宿主**：throughput 行 host 占 92–95%（单核），CUDA Graph 只值 +3.7%；MTP 接受率计数 87%、散文 15–17%。
- **池 40,000 就是上限**：52k 起得来但 prefill 崩到 ~180 tok/s（WDDM 换页），56k 直接拒启。

## 2. GPU 解锁（Zagitta/gpu-unlock）：不刷

### 2.1 它能做到什么

- 在驱动加载前把 GeForce 张量核的 FP16/BF16/TF32（FP32 累加）从半速改回全速，**不用刷 VBIOS、不用改驱动**；Windows 原生可跑（UEFI 应用早于系统）。
- 我们这张卡（`10de:2803`，4060 Ti 8GB）在社区 PR 上是**实测级**：FP16 GEMM **46.78 → 75.28 TFLOPS（+61%）**。

### 2.2 为什么对我们几乎没用（今天实测定价）

| 维度 | 收益 | 原因 |
|---|---|---|
| decode（tok/s） | **0** | 物理墙 6.3947 GB ÷ 288 GB/s ÷ 2 = 45.1 tok/s；MTP 的 107 卡在宿主 51.4 ms/轮 |
| 显存 / 上下文 | **0** | 它改的是 issue rate，不是容量或带宽 |
| prefill / 首字 | **上限 +16.3%**（保守 +8.8%） | A8 段占 63.6% 不吃这个红利，只有 36.4% 走被钳通路：`1/(0.636+0.364/1.624)=1.163` |

换算成手感：8k prefill 1,099 → ~1,269；**37k TTFT 38.9 → 33.5 s**（省 5.4 s）；200K 单发 596 → 635。

### 2.3 代价清单（为什么不值这 5 秒）

- 每次冷启动要过 5 秒固件倒数；解锁**易失**（断电/休眠即清）；驱动更新要重刷；
- 只能从「重启」进（纯 iGPU 关机会 D3cold，写入中止）；重启会打断 8091/8081；
- 本机面板已在 AMD 核显上（`display_active=Disabled`），所以社区说的「推理卡不驱动显示器 ⇒ +18~20% 首字」这**红利我们已经吃到了**，解锁不会重复给。

⇒ **NO-GO**。报告全文：`reports/解锁-研究-nvUEFI.md`（304 行，含 A/B 日志、公式、回滚、风险）。

## 3. Strata：本机起不来（28 臂实测）

| 档 | 结论 |
|---|---|
| Qwen3.6-35B-A3B UD-Q4_K_XL（22.9 GB） | **起不来**。权重 4.40 GiB 上卡后剩余 32K 0.00 / 16K 0.21 / 8K 0.60 / 4K 0.80 / 2K 0.90 GiB，引擎要 **1,159 MiB** 放专家缓冲 ⇒ 2K 也缺 **242 MiB** |
| 125B 级（Q2_0/IQ2_XS/IQ3_XXS/IQ3_S） | **装不下**：要「专家 + 约 10 GB RAM」，本机 RAM+VRAM 只有 39.2 GB；只有 Gyro-S（27.6 GB 合计）够 |
| Gyro-S | 下载中（58.49 GB）。setup 自动进 **low-RAM 模式**（专家走 OS 文件缓存、GPU 只放 ~8%），官方原文警告「会比内存够时慢很多」；社区同档 15–21 tok/s |

压不动的证据：每减半上下文只回收 200–400 MiB；`--expert-slots` 越大需求越大（1→1,235 / 8→1,759 / 32→3,559 MiB）；
`--kv q4_0`、`--no-capture`、`--conversation-cache-slots 1`、`--trim-stage-weights`、`STRATA_EMBED_VRAM=0`、`--mmap-experts` 全部无效；MTP 是权重块，去掉也不省。

最后一个没试的 `--kv-resident 20480` 也算了账，同样不是解：32K 下只省 518 MiB（仍差 641 MiB），4K 根本不触发流式。
从 2K 那臂反推，引擎自身「会话 + 缓冲」固定开销约 **2.6 GiB**，**没有开关可压** ⇒ 8 GB 上这条路是死结，不是配置没调对。

报告：`reports/Strata-8G实测-Qwen36起不来.md`。
