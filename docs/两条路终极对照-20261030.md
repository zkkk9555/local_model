# 两条路的终极对照：现役 NInfer vs Strata（RTX 4060 Ti 8GB · 2026-10-30）

> 本文件回答三个问题：① 我们现在用的和 Strata 哪个更好；② 各自在本机的极限在哪；③ Windows 上的 GPU 解锁对首字有没有用。
> 所有数字都是本机实测（同一天、同一张卡、可复跑），来源文件写在各行后面。

## 0. 一句话

**现役 NInfer（KVMem 环形池）在本机全面胜出，不是「略胜」，是一个数量级：**
上下文 **40,000 vs 1,024**（39 倍）、prefill **1,001 vs 120.9 tok/s**（8.3 倍）、decode **107 vs 42.1 tok/s**（2.5 倍），
而 200K 文档问答只有 NInfer 的分片法做到了「316 s、8/8、可重复」。

## 1. 硬碰硬（同一张卡、同一模型家族、同一天）

| 指标 | NInfer KVMem（现役，40K 池） | Strata（q36 档最省显存配置） | 倍数 |
|---|---|---|---|
| 上下文上限 | **40,000** | **512–1,024 cell** | **39 倍** |
| prefill 速度 | **1,108（8k）/ 1,001（37k）tok/s** | 90.2 / **120.9 tok/s** | **8.3 倍** |
| decode | **107 tok/s（计数）/ 41.5（散文）** | 35.3 / **42.1 tok/s** | **2.5 倍** |
| 首字（24k 提示） | **23.2 s** | 24k 装不进 1,024 cell | 不可比 |
| 权重驻留 | 6.39 GB PTQ1 全驻显存 | trunk 4.40 GiB 上卡 + 18.75 GiB 专家摊主机 | — |
| 显存峰值 | 7,459 / 8,188 MiB | 起服后只剩 1.13–1.15 GiB 余量给 KV | — |
| 200K 文档 | 分片 **316 s、8/8、连跑两次一致** | 不可能 | — |
| 能不能当主力 | **能**（DSH 已接 8081/8091） | 不能，只能当 1K 玩具 + 监控面板 | — |

> 证据：NInfer 侧 `docs/最终结论-8G-200K-三条路-20261030.md`；Strata 侧 `strata/logs/g-BENCH.log` 原文 `bench 2: pp32 120.9 tok/s, tg8 42.1 tok/s`、`context 1024 cells … 1.13 GiB of VRAM free`。

**为什么差这么多**：Strata 的设计目标是「把 125B 级 MoE 塞进小卡」，做法是把**专家**摊到主机内存/SSD，每 token 按路由去抓专家 ⇒ 显存省了，但上下文只能开 1K、每 token 都在等内存。NInfer 走另一条：模型全驻显存，把 **KV** 分页到主机、按相关度捞回来 ⇒ 40K 池、prefill 上千 tok/s。

## 2. 各自「逼到极限」是什么样

### 2.1 NInfer（现役，已是本机极限配置）

- 配置：`profile=max`（CUDA Graph allowance 16 / `--ngram-draft-tokens 0` / `--prefill-chunk 1536`）、池 40,000、KV `rk2v4-e8`、MTP draft4+win8、`--device-state-slots 0`。
- 实测：**计数题 107 tok/s、散文 41.5 tok/s、8k prefill 1,108、37k prefill 1,001、峰值 7,459 MiB（余 729）**。
- 极限外的边界：单遍 209K 只可信一次（首发 8/8 → 第二次 2/8 → 150K 0/8）；所以 200K 走分片（`tools/longdoc.py`），316 s/本。

### 2.2 Strata（本机能到的极限）

- 能起：`READY 1024`，`bench 2: pp32 120.9 / tg8 42.1`。
- 到不了：trunk 4.40 GiB + staging 1.10 GiB 已吃掉 5.5 GiB，再抬上下文就 EngineDied（28 臂全灭，缺 242–418 MiB）。
- **Gyro-S 档已实测完**（125B 级 MoE，TQ1_0，58.5 GB，`--mmap-experts`）：**上下文 32,768 真能起**（8K/16K/32K 三档全 READY，`context 32768 tokens, images on`），但代价是——
  - decode **19.0–24.4 tok/s**（对比现役 NInfer 107，慢 **4.4–5.6 倍**）；
  - 首字：warm 短问 1.30–3.52 s、冷 10.59 s、**2.2k 汉字 21.1 s、7.4k 汉字 28.7 s**（那一轮读盘 **368 GB**）；
  - 显存 7,045 / 8,188 MiB、只剩 719 MiB，引擎自己喊 `Add --vram-reserve-mib 1152`；`strata.exe` 工作集 **21.3 GB**、Windows commit 剩 24.9 GiB；
  - 预填计划自报：16,384 提示要**从磁盘读 1,661 GB**（page cache 装不下 24.2 GiB 专家集）。
  ⇒ 判定：**留作长上下文备胎，不顶替 NInfer**。它唯一比 NInfer 强的点是「模型大 4 倍还能开 32K」，但速度掉到 1/5、每轮读盘上百 GB，日常不可用。详见 `reports/Strata-GyroS-极限实测.md`。
- 全量 Qwen3.8-Flash-Next（125B）在 31.1 GB 内存上只能磁盘 mmap，他人实测 32K 提示要读 519 GB 盘——本机不开这条路。

## 3. Windows GPU 解锁（physicsdolphin/nv-uefi-unlocker）对首字有用吗？——**NO-GO**

先纠正一个容易搞错的点：那条「prefill 74.8 tok/s / 334.8 s」是 **llama.cpp** 的（`logs/llama8g-launch.log:218`），不是 NInfer。NInfer 24k 是 **1.03k tok/s / 首字 23.2 s**，快 13 倍——拿 llama 的 13.37 ms/token 去套解锁收益会严重高估。

**实测反推**（`--no-prefill-a8` A/B 两组对照：8k 1,100→396.7 = 2.777×；24k 1,030→386.2 = 2.664×）：

- **被钳的 A16 通路只占 prefill 时间的 36.4%**，其余 63.6% 本来就走不加锁的 int8 通路。
- 所以解锁**理论上限 = 1/(0.636 + 0.364/1.624) = ×1.163**；保守（×1.088 再减半）也就 ×1.04。
- 落到首字：**8k −1.0 s、24k −3.3 s、37k −5.4 s**；decode **+0**；显存 **+0**。

**为什么仍然 NO-GO**：

1. 收益只有 1–5.4 秒，而我们真正的两个痛点（8 GB 容量、decode 已被带宽/主机往返卡住）它一点不动。
2. 这个项目是 **UEFI 预驱动事务**（SEC2→FWSEC/WPR2→签名 Booter→V67 四写→读回→FLR→链回 bootmgfw），**每次冷启动都要过一遍 U 盘 + 5 s 倒数**，解锁**易失**，必须关 Secure Boot（本机已 False），回滚=强制重启。
3. 风险是真的：issue #61（4070 Ti S + X570）GOP 停滞→**Windows Code 12**、#35 同类、#55 引导无显示+蓝屏。本机 AM5 + 616.92 + 26100 + GameViewer IDD 组合**无先例**。
4. 好消息：**2803 桌面卡本身在支持面**（PR #5 实测 46.78→75.28 TFLOPS，issue #51 +64%）；回看条件写在 `reports/UEFI解锁-Windows-对首字影响.md`：**只有当 A16 通路占比 ≥60% 时才值得重算**。

## 4. 「更好」到底怎么算

| 你的用法 | 该用谁 | 理由 |
|---|---|---|
| 日常问答 / 写代码（≤36K） | **NInfer 40K 池** | 107 tok/s decode、37k prefill 1,001、首字 23 s |
| 一份 200K 文档要问答 | **NInfer + 分片** | 316 s、8/8、可重复；Strata 连接口都开不到这个长度 |
| 同一份长文反复追问 | **llama.cpp 262K**（第三条路） | 建好后每次 0.9–1.1 s；但首读 O(n²) |
| 想看硬件占用 / 想要 GUI | **Strata 桌面版** | Tauri 桌面端，GPU 利用率/显存拆分/功耗/温度/CPU 全有；但模型只能 1K |
| 想省显存跑超大模型 | **都不用** | 8 GB 上这是伪需求：权重都放不下的模型，摊到内存就是 15–42 tok/s |

## 5. 结论

1. **现役这套就是本机最优解**，已调到它的极限（107 tok/s / 40K 池 / 7,459 MiB，余 729 MiB 安全垫）。
2. **Strata 在本机打不过**：能起，但 1,024 上下文 + 42 tok/s，只能当「另一个可选引擎 + 硬件监控面板」。
3. **GPU 解锁不值得做**：上限 +16.3% 的 prefill 折到首字只省 1–5 秒，代价是整机变砖风险 + 每次冷启动插 U 盘。
4. 真正还能再快的方向在**软件侧**：前缀缓存（同 67k 提示 84.2 s → 0.54 s）、分片并发、`--prefill-chunk` 调优——已固化在 `switch.sh` / `asklong.sh`。
