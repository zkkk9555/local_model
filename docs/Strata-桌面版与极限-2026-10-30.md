# Strata 桌面版与极限 — 2026-10-30（RTX 4060 Ti 8 GB + 31 GB DDR5）

> 本机：Ryzen 7 7800X3D / 31.1 GB / RTX 4060 Ti 8 GB (sm_89, 34 SM, 288 GB/s) / Win11 / 驱动 616.92
> 仓库：`C:/Project/local_model/strata`（112 GB）。生产服务始终是 `scripts/serve.sh` → 8091 NInfer（未改动，实测全程未被踩死）。

## TL;DR

| 问题 | 答案 |
|---|---|
| 桌面版还是网页？ | **两者都是**：Tauri(Rust) 原生窗口 + WebView2 渲染 + 捆绑 node.exe 起的本地 HTTP 服务（网页 UI 跑在 localhost 随机端口）。不是 Electron，没有 app.asar。 |
| 启动会踩死 NInfer 吗？ | **不会**（这次实测）。它启动时不加载任何模型：没有引擎包就直接报 "No Strata engine for this PC"。显存 40 s 内恒定 7,680 MiB、8091 恒定 200。 |
| 能看到全部硬件占用吗？ | **GPU/CPU/内存/磁盘四类齐全**（本地 JSON 端点），GPU 侧 12 个读数（利用率/显存/功耗/温度/PCIe/风扇/时钟），连核显一起报。传感器级细节（内存通道、每核温度）没有。 |
| 本机怎么装最合适？ | **不要**用桌面版自带的 Update engine（下到用户目录、体积不可控）。仓库 CLI 版（`serve/server.py`）继续当主力入口；迷你 q36 档只为"看 UI"，长上下文用 Gyro-S 8K/16K。 |
| 极限多少？ | **上下文 32,768 实测起得来**（GPU 峰值 7,045 MiB，只剩 719 MiB free）；decode **19.0–24.4 tok/s**；首字 warm 1.3–3.5 s / 冷 7.5–10.6 s / 2.2k 汉字 21.1 s / 7.4k 汉字 28.7 s。 |

## 一、它是什么（桌面端 / 网页 / 引擎在哪）

### 1.1 三层结构（实测证据）

```
strata-desktop.exe (Tauri, Rust 壳, 10,155,520 B, PE machine 0x8664)
  └─ msedgewebview2.exe ×多   ← WebView2 渲染进程（网页 UI 在这里画）
  └─ app\node\node.exe  app\host\server\index.mjs   ← 本地 HTTP 服务（端口随机）
       └─（有引擎时）拉起 control\python\python.exe serve\server.py --engine strata
```

- 判据：exe 内部字符串 `tauri`×130 / `Tauri`×44 / `WebView2`×12，而 `electron` 只出现 2 次、`CEF` 1 次；`strata/app` 下**没有** `resources/app.asar`，也没有 Electron 的 `chrome_100_percent.pak` 之类。
- `strata/app/` 五件套：`control` 234 M（控制层 + 自带 python）、`harness` 273 M（=`@deepseek-ai/dsh` 0.2.1-alpha.3，DSH 本体）、`host` 14 M（`strata` 0.2.8，web shell + engine host）、`node` 86 M（node.exe）、`uninstall.exe`。
- 所以：**UI 是网页，外壳是原生窗口，引擎是外挂进程**。三层可以拆开单独用——这点很重要，见 1.4。

### 1.2 端口：随机，且不认 --port

- 启动日志写 `strata host · http://127.0.0.1:47831`（`strata/logs/desktop-*.log`）。**每绑一次换一个号**。
- host 源码 `strata/app/host/server/index.mjs:100`：`PORT = Number(process.env.STRATA_PORT ?? 8791)`。
- 我传 `--port 8096` **无效**；要固定端口必须 `STRATA_PORT=8096`（实测有效，见 2.3）。

### 1.3 数据目录：桌面版和我们装的东西互不相见（关键坑）

| 目录 | 谁在用 | 内容 |
|---|---|---|
| `C:\Users\Administrator\Documents\Strata\{Models,Workspace}` | 桌面版默认 | 启动时**自动创建**，空的 |
| `%LOCALAPPDATA%\Strata\{components,install,logs,procs,runtime,shell-prefs.json}` | 桌面版默认 | 启动时自动生成；引擎必须放在 `components` 里 |
| `C:/Project/local_model/strata\{components,install,model-data,app}` | 我们（仓库版） | Gyro-S / qwen36 GGUF / 已装引擎 |

桌面版日志原文：

> `inference · No Strata engine for this PC. No engine for this PC was found in C:\Users\Administrator\AppData\Local\Strata\components: the component folder holds no engine package. The app never downloads an engine while it starts or serves.`

⇒ **仓库里装好的引擎，桌面版看不见**。要用桌面 UI 必须让它在 Settings 里 Update engine（下到 `%LOCALAPPDATA%`），或者把 components 指过去（`STRATA_COMPONENTS_DIR`，未在桌面版里验证）。

### 1.4 桌面版的隐性代价

- 它启动的是"壳 + 空引擎"，看着能开，实际一问就 500；要在 UI 里能聊天，还得再下一次引擎（几百 MB 到几十 GB，落点不在仓库）。
- 仓库版 CLI 路径（`app/control/python/python.exe serve/server.py --engine strata --config install/xxx.json --port 8095`）是**同一套控件**，只是没有 Tauri 壳。测速、调参、换引擎都走这条，桌面版只当"看界面"用。

`phase, phaseLabel, variantId, prompt{done,total,pct}, generation{done,total}, outputTps, promptTps, queue{running,waiting}, context{usedTokens,maxTokens,pct,parts}, expertCache{used,total}, hardware, requests, conversationCache, history, totals, telemetry, engine`

- 空闲快照实测：`{"phase":"idle","phaseLabel":"Waiting for a request","outputTps":0,"promptTps":0,"queue":{"running":0,"waiting":0}}`。

### 2.3 `GET /api/engine/status` 与 `/api/health`

- `engine/status`：`status, running, binary, pid, port, modelId, modelPath, startedAt, error, args, command, metrics{source,promptTokens,predictedTokens,promptTps,outputTps,kvUsage,kvTokens,requestsProcessing,requestsDeferred,sampledAt}, logCount` —— **连启动 argv 都给了**，排障很省事。
- `health`：`{ok, uptimeSec, backend{kind,name,baseUrl,models,error}}`。
- 另有 `/api/events`(SSE) / `/api/models` / `/api/native/*` / `/api/app/*`，共约 60 条路由。

### 2.4 能看到的 GPU 读数上限（源码级）

`strata/app/host/server/device-probes.mjs:45 parseNvidiaReadings()` 解析：

`temperatureC / utilizationPct / memoryUsedGb / powerW / powerLimitW / pcieGen / pcieGenMax / pcieWidth / pcieRxMbs / fanPct / clockMhz`

外加 `parsePcieThroughput`、`parseCpuTopology`、`windowsGpuReading`（非 N 卡的兜底）。

**能看到**：GPU 利用率/显存/功耗/功耗墙/温度/风扇/核心时钟/PCIe 代宽与链路速率、CPU 拓扑与主频、内存总量与占用与 pressure、磁盘容量。
**看不到**：内存通道/频率/每核温度、NVMe 温度与 SMART、CPU 单核频率、网络。
（对我们的用途——判断"现在有没有踩满 8 GB、是不是被 PCIe 卡住"——够用。）

## 三、怎么装（8 GB 显存 + 31 GB 内存的最优解）

### 3.1 结论：不要走"桌面版 + Update engine"

理由三条：① 引擎下到 `%LOCALAPPDATA%\Strata\components`，和仓库版重复占盘（C: 只剩 36 GB）；② 下哪个规格不可控，8 GB 卡上大规格必然起不来；③ 我们已有可直接跑的仓库版 + 现成配置，桌面版只多一层壳。

### 3.2 推荐分工（本机）

| 用途 | 用什么 | 端口 | 读数 |
|---|---|---|---|
| 日常生产 | NInfer（`scripts/serve.sh`，池 32,000 / ctx 262,144 / kv rk2v4-e8 / MTP） | 8091 | **98 tok/s**（计数型），偏散文 48.5–50.0，prefill 842–965 |
| 长文档整篇吞 / 跨段落引用 | **Gyro-S `--max-context 8192`（首选）或 16384** | 8095 | decode 19.0–24.4，首字 1.3–3.5 s(warm) / 21.1 s(2.2k 汉字) / 28.7 s(7.4k 汉字) |
| 只想看 UI / 试桌面版 | 迷你 q36 档（`--chunk 128 --no-graph`，ctx 256/512/1024） | 8095+ | tg 35.3–42.1 tok/s，pp 90.2–120.9，但上下文只有 1 K |

### 3.3 CPU-only 要不要？

**不要。** 8 GB 卡上 Gyro-S 连 32 K 都起得来（7,045 MiB），没必要把算力交给 CPU；CPU-only 会把 decode 从 20 掉到个位数，省下的显存换不来任何东西。

### 3.4 112 GB 里哪些能删（**候选清单，删前须 lead 点头；`strata/` 下不擅自删**）

| 目标 | 大小 | 判断 |
|---|---|---|
| `strata\Strata-0.2.8-windows-x64-setup.exe` | 108 M | 已安装完，**可删**（重新下载即可） |
| `strata\model-data` 里的 qwen36 那套 GGUF | 22.85 GB（+mmproj 0.9 GB） | **可删**：128 K 在 8 GB 上是算术上限，实测 2048 都差 242 MiB；保留 Gyro-S 即可 |
| Gyro-S 的 58.49 GB | 58.49 GB | **不能删**：它是这台机器唯一实测能到 32 K 的长上下文 |
| `model-data\mtp` | — | 用 `--spec 4` 就必须留（接受率 19/22、21/27） |
| `components` 里未用的后端包（cuda12/cuda13/hip/rdna3/rx9070/sycl/metal 变体） | 902 M 总量 | 可清一半，收益小，优先级低 |
| `app\control` / `app\harness` / `app\node` | 234+273+86 M | **不能删**（CLI 与 DSH 都靠它） |

粗算：删 setup + qwen36 一套 ≈ **省 24 GB**，C: 从 36 GB → 60 GB。**收益最大且零风险的就是这两项。**

## 四、极限多少（实测，不是推算）

### 4.1 上下文上限：**32,768 实测起得来**

| ctx | 起服日志 | GPU | free 提示 |
|---|---|---|---|
| 8192 | `context 8192 tokens` | 6,684 MiB | `719 MiB of VRAM free with everything loaded` |
| 16384 | `context 16384 tokens` | 6,641 MiB | 719 MiB |
| **32768** | `context 32768 tokens, images on` | 6,899 → **7,045 MiB** | 719 MiB；请求时引擎再报 `WARNING: only 573 MiB of VRAM free at the start of this request (below 1024 MiB) ... Add --vram-reserve-mib 1152` |

- **上限判定：32 K 是"能起、能答"的实测值**；它不是 KV 显存卡住的（三档 free 都是 719 MiB，KV 是 int8 且按需），真正压着的是**内存**：32 K 臂 `strata.exe` 进程 WS **21.3 GB**（21,312,944 K）+ `strata-vision.exe` 1.08 GB，引擎自己写 `windows commit: 24.9 GiB left of a 54.1 GiB limit`。
- 再往 64 K：没试（也不敢试）——预填的页面缓存计划已经写明 `file set 24.1 GiB does not fit the page cache 15.3 GiB -> about 414.8 GB read from the drive per 8192-token prompt`，64 K 会是 8× 磁盘读 + 40 GB 级内存。**结论：本机安全上限 = 32 K，日常建议 8–16 K。**
- 32 K 配置必须去掉 `--vision`？不需要——我们那条本来带 `--vision` 的 `install/strata-gyro-gyro-s.json`（ctx 32768）实测起得来，还带 `images on`。

### 4.2 decode：**19.0–24.4 tok/s**

| 臂 | 引擎日志原文 | tok/s |
|---|---|---|
| 8 K / 2,207 prompt / 48 out | `48 generated in 2531 ms (19.0 tok/s), drafts accepted 29 of 36` | 19.0 |
| 8 K / 7,447 prompt / 32 out | `32 generated in 1311 ms (24.4 tok/s), drafts accepted 19 of 22` | 24.4 |
| 32 K / 2,207 prompt / 32 out | `32 generated in 1434 ms (22.3 tok/s), drafts accepted 21 of 27` | 22.3 |

预填（prefill）：`prompt 2207 tokens ... (119.1 tok/s)` → `prompt 7447 tokens ... (272.3 tok/s)`（越长越快，因为 chunk 512 的流水打得开）。

### 4.3 首字（TTFT）

| 场景 | 首字 | 说明 |
|---|---|---|
| 短问（59 prompt tok）**冷** | **10.59 s** | 第一次请求要读专家到 RAM/GPU |
| 短问 warm | **1.30–3.52 s** | 会话缓存已驻留（`conversation cache: parked 157 tokens ... reused_kv_bytes`） |
| 2,207 prompt tok（3,362 汉字） | **21.09–21.23 s** | 8 K 与 32 K 臂几乎一样 |
| 7,447 prompt tok（11,402 汉字） | **28.72 s** | 该轮累计磁盘读 **367.7 GB** |

### 4.4 值不值得留？

| 维度 | NInfer 现役（8091） | Gyro-S（8095） |
|---|---|---|
| decode | **98 tok/s**（计数型；散文 48.5–50.0） | 19–24 tok/s |
| 上下文 | 池 32,000（KV 落盘 3.0 GiB，总 ctx 262,144） | **32,768** |
| 首字（短问 warm） | 亚秒级 | 1.3–3.5 s |
| 首字（7k 汉字） | 数秒级 | 28.7 s |
| 显存 | 7,074/8,188 MiB（余 507） | 7,045/8,188 MiB（余 1,143） |
| 单轮成本 | 无额外磁盘读 | 7.4k 提示要读 368 GB → **必须 SSD 且别和别的重 IO 抢** |

**结论**：Gyro-S **不值得顶替 NInfer**（慢 4–5 倍，上下文并不更大），**值得留作长上下文备胎**：一次要吞 >5k token 的整篇材料、且不在乎等 20–30 s 首字时，用 8 K 或 16 K 臂；其余时间 8091 不动。

## 六、遗留与注意

- 桌面版**启动不占显存、不杀 NInfer**（本次 40 s 采样：GPU 恒 7,680 MiB、8091 恒 200）；但一旦在 UI 里加载引擎，就会和 NInfer 抢 8 GB —— 那时必须先停 8091。
- 还原后 `netstat` 见到 **8081 有两个 LISTENING（pid 33232 与 3588）**，8091 正常 200、GPU 7,637 MiB。属于网关重复绑定，不影响推理，但值得清一次。
- Gyro-S 起服前一定用**正斜杠**写 `CFG=`（`\` 在 `${VAR:-word}` 里会被吞掉，报 `FileNotFoundError: 'C:Projectlocal_model...'`）。
- 引擎日志里 `STRATA_ROUTE_TAIL_SKIP=7 is ON (default)` 会让"答案与原版略有差异"，要严格一致就设 `STRATA_ROUTE_TAIL_SKIP=0`（会掉 10–20% decode）。
